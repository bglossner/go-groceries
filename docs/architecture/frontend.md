# Frontend architecture

The frontend uses React 18, TypeScript, Vite, MUI/Emotion, TanStack Router and React Query, Dexie, Zustand, React Hook Form/Zod, and dnd-kit. React's entry mounts `App` in StrictMode. `App` creates one router from the generated route tree and one QueryClient, then wraps routed content in Toast and DiffsModal providers. Sources: [package.json](../../apps/frontend/package.json), [main.tsx](../../apps/frontend/src/main.tsx), [App.tsx](../../apps/frontend/src/App.tsx).

## Routes and page responsibilities

The Vite TanStack Router plugin works with file routes and [routeTree.gen.ts](../../apps/frontend/src/routeTree.gen.ts). The root route supplies the app bar and outlet, and redirects `/index.html` to `/`. Sources: [vite.config.ts](../../apps/frontend/vite.config.ts), [__root.tsx](../../apps/frontend/src/routes/__root.tsx).

| Route | Route/page source | Behavior |
| --- | --- | --- |
| `/` | [index.lazy.tsx](../../apps/frontend/src/routes/index.lazy.tsx) | Welcome, backup export/import, shortcut to last edited list. |
| `/meals` | [meals.lazy.tsx](../../apps/frontend/src/routes/meals.lazy.tsx), [Meals.tsx](../../apps/frontend/src/pages/Meals.tsx) | Meal CRUD, name search, tag filtering, sorting, manual/YouTube/image creation selection, recipe navigation, add-to-list modal. |
| `/grocery-list` | [grocery-list.lazy.tsx](../../apps/frontend/src/routes/grocery-list.lazy.tsx), [GroceryList.tsx](../../apps/frontend/src/pages/GroceryList.tsx) | List CRUD, meal selection and custom ingredients; aggregated-ingredient dialog with All/specific-store filtering. |
| `/go-grocery` | [go-grocery.lazy.tsx](../../apps/frontend/src/routes/go-grocery.lazy.tsx), [GoGrocery.tsx](../../apps/frontend/src/pages/GoGrocery.tsx) | Validates a numeric `groceryListId` search value and renders the shopping checklist. |
| `/manage-stores` | [manage-stores.lazy.tsx](../../apps/frontend/src/routes/manage-stores.lazy.tsx), [ManageStores.tsx](../../apps/frontend/src/pages/ManageStores.tsx) | Select a store and edit its ingredient checklist. Create, color, and delete stores in the management dialog. |

Meal generation uses `VITE_YOUTUBE_API_BASE_URL`; the pass comes from IndexedDB setting `youtubeApiPass`, falling back to `VITE_YOUTUBE_API_PASS`. The response prefills a form rather than writing a meal directly. The image dialog does not make an API request. Sources: [FromYoutubeMealCreation.tsx](../../apps/frontend/src/components/FromYoutubeMealCreation.tsx), [Meals.tsx](../../apps/frontend/src/pages/Meals.tsx), [FromImagesMealCreation.tsx](../../apps/frontend/src/components/FromImagesMealCreation.tsx), [environment declarations](../../apps/frontend/src/vite-env.d.ts).

Recipe validation allows up to 10 images, 500 URL characters, and 10,000 notes characters. Uploaded/captured images are compressed with a 1 MB and 1920-pixel configuration; image URL additions are checked through browser image loading. URL validation for the recipe's text URL itself is only a string-length check. Sources: [recipe schema](../../apps/frontend/src/types/recipe.ts), [images.ts](../../apps/frontend/src/util/images.ts), [recipe route](../../apps/frontend/src/routes/recipe.$mealId.tsx).

## State, contexts, and hooks

Dexie owns meals, lists, recipe data, stores, settings, sync locations, and checkbox state. React Query wraps asynchronous Dexie reads and mutations as well as network operations; it is not a separate server database. Callers explicitly invalidate query keys after mutations. `useSetLastEditedGroceryListId` persists a string setting and invalidates the shortcut query. Sources: [db.ts](../../apps/frontend/src/db/db.ts), [Meals.tsx](../../apps/frontend/src/pages/Meals.tsx), [useSetLastEditedGroceryListId.ts](../../apps/frontend/src/hooks/useSetLastEditedGroceryListId.ts), [settings utility](../../apps/frontend/src/util/db/settings.ts).

The only Zustand store is an in-memory queue of DB mutation records plus callbacks; it is neither durable nor a queue of serialized replay operations. React state owns dialogs, search/filter/sort controls, drag overlays, form state, and shopping accordion expansion. Sources: [mutationQueueStore.ts](../../apps/frontend/src/store/mutationQueueStore.ts), [Meals.tsx](../../apps/frontend/src/pages/Meals.tsx), [ManageStores.tsx](../../apps/frontend/src/pages/ManageStores.tsx), [GroceryListContainer.tsx](../../apps/frontend/src/components/GroceryListContainer.tsx).

`ToastProvider` exposes success/error/action snackbars through `useToast`; normal toasts expire after five seconds, action toasts stay open. `DiffsModalProvider` stores the downloaded blob and meal-name changes, imports on confirmation, records sync success, and invalidates `syncFrom`. `useDiffsModal` exposes the modal actions and forwarded toast functions. Sources: [ToastProvider.tsx](../../apps/frontend/src/contexts/ToastProvider.tsx), [useToast.ts](../../apps/frontend/src/hooks/useToast.ts), [DiffsModalProvider.tsx](../../apps/frontend/src/contexts/DiffsModalProvider.tsx), [useDiffsModal.ts](../../apps/frontend/src/hooks/useDiffsModal.ts).

## Shopping and store assignments

`GroceryListContainer` aggregates ingredients by lowercased name, sums quantities (default 1), and keeps source descriptions. Flat mode places checked ingredients last and sorts alphabetically within checked/unchecked groups. Store mode copies an ingredient into every assigned store and leaves unassigned ingredients in Uncategorized; checked state is shared by ingredient name across those copies. Store groups follow map insertion order, while ingredients inside groups are alphabetized. Sources: [GroceryListContainer.tsx](../../apps/frontend/src/components/GroceryListContainer.tsx), [grocery-list view types](../../apps/frontend/src/types/grocery-list-types.ts), [PartitionedGroceryList.tsx](../../apps/frontend/src/components/PartitionedGroceryList.tsx), [StoreAccordion.tsx](../../apps/frontend/src/components/StoreAccordion.tsx).

Current limitations matter when changing these components: named-store search retains an entire group if any row matches, whereas Uncategorized filters rows; completion counts store appearances while checked names are unique; and the first expansion toggle stores `true` for an absent map entry although the rendered default is already `true`. The arrow IconButton is nested inside AccordionSummary. These are source-level issues described in the [earlier branch analysis](../analysis/unsure-branch-last-3-commits.md); no fix is part of these docs. Sources: [PartitionedGroceryList.tsx](../../apps/frontend/src/components/PartitionedGroceryList.tsx), [GroceryListContainer.tsx](../../apps/frontend/src/components/GroceryListContainer.tsx), [StoreAccordion.tsx](../../apps/frontend/src/components/StoreAccordion.tsx).

Store management aggregates unique lowercased names from meals and custom ingredients and includes saved links for ingredients that left the catalog. Each checkbox writes one store and ingredient pair. Undo reverses the latest saved checkbox edit. Deleting a store removes its assignments in the same transaction. Sources: [ManageStores.tsx](../../apps/frontend/src/pages/ManageStores.tsx), [StoreManagementDialog.tsx](../../apps/frontend/src/components/StoreManagementDialog.tsx), [storeAssignments.ts](../../apps/frontend/src/util/storeAssignments.ts).

## Snapshot sync

Sync controls use `VITE_FILE_SYNC_BASE_URL` and the saved `youtubeApiPass`. The upload path exports the selected tables, requests an R2 PUT URL, uploads directly, requests a GET URL, and stores a `to` location. A caller that supplies an existing location reuses its filename. Current manual SyncSettings calls omit that existing record, so they create a new filename/location even when one is already displayed. Sources: [SyncSettings.tsx](../../apps/frontend/src/components/SyncSettings.tsx), [useSyncTo.ts](../../apps/frontend/src/hooks/useSyncTo.ts), [sync.ts](../../apps/frontend/src/util/sync.ts).

A `from` location is parsed from a signed URL, including filename and expiry. `syncFromDb` refreshes the GET URL when less than 60 seconds remain, downloads a blob, and computes meal-name additions/removals in a temporary DB. Manual sync opens the confirmation dialog when names change and otherwise imports directly. Snapshot replacement and its failure limits are documented in [Data model](data-model.md). Sources: [sync-from.ts](../../apps/frontend/src/util/sync-from.ts), [SyncSettings.tsx](../../apps/frontend/src/components/SyncSettings.tsx), [s3-presigned.ts](../../apps/frontend/src/util/file/s3-presigned.ts), [import.ts](../../apps/frontend/src/util/db/import.ts).

Automatic checks require a location with `automatic` enabled and an existing `lastSyncedAt` older than one hour. Mounted `AppWrapper` runs these checks as queries with five-minute stale times; there is no configured hourly polling interval. Its download success path opens the modal for changed meal names, but for unchanged names it only records sync success and does not import the snapshot. Sources: [App.tsx](../../apps/frontend/src/App.tsx), [sync-from.ts](../../apps/frontend/src/util/sync-from.ts), [sync-to.ts](../../apps/frontend/src/util/sync-to.ts).

`useSync` is an alternate hook with similar download/import logic, but no caller imports it in this tree and its periodic interval is commented out. `useSyncTo` wraps upload mutations, query invalidation, and notifications. Mounted `useDebouncedSync` waits five seconds after queued writes when automatic upload is enabled. DB wrappers only intercept table `put/add/delete/update` on included tables other than groceryListStates; bulk operations, collection deletes, settings, sync records, and checkbox writes do not enter this mechanism. The queue records the operation before its promise completes and is cleared in `finally` even after failed upload; there is no durable retry guarantee. Sources: [useSync.ts](../../apps/frontend/src/hooks/useSync.ts), [useSyncTo.ts](../../apps/frontend/src/hooks/useSyncTo.ts), [useDebouncedSync.ts](../../apps/frontend/src/hooks/useDebouncedSync.ts), [db.ts](../../apps/frontend/src/db/db.ts), [mutationQueueStore.ts](../../apps/frontend/src/store/mutationQueueStore.ts).

## PWA, build modes, and diagnostics

Only `pwa` and `pwa-test` modes add VitePWA. Configuration uses auto-update registration, listed asset precaching, broad CacheFirst runtime matching, outdated-cache cleanup, and enabled development support. The manifest starts at `/index.html`, uses standalone display and public icons/screenshots, and adds a Test suffix in test mode. Both PWA modes configure port 5174, host exposure and unrestricted allowed hosts; ordinary Vite mode uses its defaults. Sources: [vite.config.ts](../../apps/frontend/vite.config.ts), [package.json](../../apps/frontend/package.json), [root redirect](../../apps/frontend/src/routes/__root.tsx).

The update-notification hook is currently inert: `needRefresh` remains false, `updateServiceWorker` is a no-op, and `useRegisterSW` is commented out. This does not negate the plugin's build-time registration configuration, but the custom Reload toast is not wired to update state. `InstallPWAButton` captures `beforeinstallprompt`; App omits it when already in standalone display. Sources: [useSWUpdate.tsx](../../apps/frontend/src/hooks/useSWUpdate.tsx), [InstallPWAButton.tsx](../../apps/frontend/src/components/InstallPWAButton.tsx), [App.tsx](../../apps/frontend/src/App.tsx).

React Query devtools appear in development or PWA test mode, with a console overlay on mobile in those modes. The overlay intercepts log/error calls and retains ten messages. The YouTube mock is checked in but its return path is commented out. Sources: [App.tsx](../../apps/frontend/src/App.tsx), [DebugConsole.tsx](../../apps/frontend/src/pages/DebugConsole.tsx), [FromYoutubeMealCreation.tsx](../../apps/frontend/src/components/FromYoutubeMealCreation.tsx), [mocks/youtube.ts](../../apps/frontend/src/mocks/youtube.ts).
