# Backend workers and shared library

Both apps export Hono applications, register wildcard OPTIONS handling, apply CORS middleware, and mount explicitly listed POST routes. Both Wrangler files point to `src/index.ts`, enable observability and workers_dev, and the YouTube Worker also enables Node compatibility. Neither entry registers Swagger, OpenAPI generation, or chanfana. Their [YouTube README](../../apps/go-groceries-youtube-meal-resolver/README.md) and [images README](../../apps/go-groceries-images-meal-resolver/README.md) retain template claims absent from current code. Sources: [YouTube index.ts](../../apps/go-groceries-youtube-meal-resolver/src/index.ts), [images index.ts](../../apps/go-groceries-images-meal-resolver/src/index.ts), [YouTube wrangler.jsonc](../../apps/go-groceries-youtube-meal-resolver/wrangler.jsonc), [images wrangler.jsonc](../../apps/go-groceries-images-meal-resolver/wrangler.jsonc), both package manifests linked in [Overview](overview.md).

## Common contracts and authorization

Implemented handlers parse JSON with `req.json<T>()`; the generic is not runtime schema validation. Malformed JSON returns 400. YouTube generation and file upload/retrieval enforce a body `pass` against `PASS`, unless the `ENABLE_PASS` switch disables enforcement; a rejected pass returns 403. There is no user account/resource-owner check in those handlers. The image-generation stub does not implement this check. CORS allows any origin, GET/POST/OPTIONS and Content-Type, and OPTIONS returns 204. Sources: [YouTube handler](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [upload handler](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-upload.ts), [retrieval handler](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-retrieval.ts), [image stub](../../apps/go-groceries-images-meal-resolver/src/endpoints/generate-meal-data-from-images.ts), [YouTube CORS](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/cors.ts), [images CORS](../../apps/go-groceries-images-meal-resolver/src/endpoints/cors.ts).

Shared HTTP errors have shape `{ error: string }`. Worker ErrorWrapper subclasses add a status code through the shared backend class. Unexpected errors in the main YouTube/file operations are logged and returned as generic 500 responses. No full validation middleware guarantees sensible property types for all JSON bodies. Sources: [response.ts](../../apps/frontend/src/shareable/response.ts), [shared error.ts](../../libraries/shared-backend/src/endpoints/error.ts), [YouTube handler](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [images types.ts](../../apps/go-groceries-images-meal-resolver/src/types.ts), [upload handler](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-upload.ts).

## YouTube Worker

### POST `/youtube/generate-meal-data`

The request contract is `GenerateMealDataYoutubeRequestInput`: required `url` and `pass`; optional `availableTags` and `additionalInput`. Options support logModelResponse, logModelRequestInput, modelSelection (Groq client plus optional model), skipAnyCaching, and the YouTube discriminator/logYouTubeResponse. The frontend builds these options in its advanced controls. Sources: [shareable/meals.ts](../../apps/frontend/src/shareable/meals.ts), [YouTube types.ts](../../apps/go-groceries-youtube-meal-resolver/src/types.ts), [FromYoutubeMealCreation.tsx](../../apps/frontend/src/components/FromYoutubeMealCreation.tsx).

The handler resolves an 11-character video ID from common YouTube URL forms and calls YouTube Data API v3 `videos.list` for the snippet. It captures title, description, channel ID, standard thumbnail and tags. It paginates `commentThreads.list` and retains only top-level comments whose author channel matches the video's channel; it does not enumerate replies or retrieve transcripts. The request sets maxResults to 250; whether that value is accepted by the external API has not been verified here. Sources: [generate-meal-data.ts](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [YouTube dependency](../../apps/go-groceries-youtube-meal-resolver/package.json).

Missing URL, unresolvable video, missing channel, or no description/uploader comments produce 400; missing YouTube key produces 500. The Worker caches SDK instances by key in module-level objects. Extraction builds a prompt from metadata/comments/available tags, asking for JSON containing mealName, ingredients, tags and recipe; quantities are requested as 1-10 with measurements defaulting to 1. These are prompt instructions, not schema-enforced model-output guarantees. Sources: [handler](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [model-interface.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/model-interface.ts), [groq.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/groq.ts).

The success response is `{ data: { name, ingredients, tags, recipe: { url, notes, images } }, modelUsed? }`; recipe images contain the standard thumbnail URL when present. It transforms internal mealName/recipe text into the frontend envelope. The [existing example_response.md](../../apps/go-groceries-youtube-meal-resolver/example_response.md) is a historical extraction example, not this envelope. Sources: [handler response](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [shared contract](../../apps/frontend/src/shareable/meals.ts).

### Groq selection, fallback, and cache

The only implemented client is Groq. The ordered fallback list in source is `moonshotai/kimi-k2-instruct-0905`, `moonshotai/kimi-k2-instruct`, `llama-3.3-70b-versatile`, `openai/gpt-oss-120b`, `llama3-70b-8192`, `gemma2-9b-it`, and `llama3-8b-8192`. On a cache miss or when cache reads are bypassed, explicit model selection tries only that model; an unknown listed-model selection produces 404. A video-ID cache hit happens before model-name validation and can ignore the requested model and return an earlier extraction. Attempts request JSON-object output, catch errors and continue through the chosen list; 429 headers are logged and can contribute a retry hint, but there is no backoff wait in this loop. All failed attempts produce 500. This list describes code, not current vendor availability. Source: [groq.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/groq.ts).

The temporary canned response branch is disabled. `CACHED_RESPONSES` is declared as a Map but used via bracket property assignment and the `in` operator; content is keyed only by video ID, not requested model, prompt or tags. This is an unusual in-memory property cache with no TTL or durable storage guarantee. `skipAnyCaching` bypasses reads but the request path still writes cache content. Cached results report a cache marker as modelUsed. Groq content is parsed with JSON.parse rather than a runtime result schema. Source: [groq.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/groq.ts).

## Images/file Worker

### POST `/images/generate-meal-data`

The registered handler only parses JSON and returns 400 if parsing fails. It has no success response, pass check, image processing, model invocation or persistence implementation. Its declared images request still has a `url` field. The frontend's From Images dialog is also a placeholder. Do not treat the route as a working image-to-meal API. Sources: [images entry](../../apps/go-groceries-images-meal-resolver/src/index.ts), [stub](../../apps/go-groceries-images-meal-resolver/src/endpoints/generate-meal-data-from-images.ts), [shared meal types](../../apps/frontend/src/shareable/meals.ts), [frontend placeholder](../../apps/frontend/src/components/FromImagesMealCreation.tsx).

### File routes

| Route | Request | Success | Validation/failure behavior |
| --- | --- | --- | --- |
| POST `/file-upload` | `pass`, `fileUploadType: 'R2'`, `fileName`, `contentType` | `{ url }`, signed PUT URL valid for 300 seconds | 400 for unsupported content/storage type or missing filename; 403 pass rejection; unexpected signing failure 500. |
| POST `/file-retrieval` | `pass`, `uploadedType: 'R2'`, `fileName` | `{ url }`, signed GET URL valid for 24 hours | 400 for unsupported storage type or missing filename; 403 pass rejection; HEAD failure maps to 404; other unexpected failures 500. |

Allowed content types are application/json, image/jpeg, image/png, image/webp, and application/octet-stream. The Worker does not receive or inspect the uploaded object body; PUT goes directly from browser to object storage. Sources for the table and allowlist: [file-upload contract](../../apps/frontend/src/shareable/file-upload.ts), [file-retrieval contract](../../apps/frontend/src/shareable/file-retrieval.ts), [upload endpoint](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-upload.ts), [retrieval endpoint](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-retrieval.ts), [PUT signer](../../apps/go-groceries-images-meal-resolver/src/file-upload/r2-presign.ts), [GET signer](../../apps/go-groceries-images-meal-resolver/src/file-upload/r2-presign-get.ts), [browser PUT](../../apps/frontend/src/util/file/file-upload.ts).

The S3 SDK client targets Cloudflare's R2 endpoint with region auto and explicit credentials. Clients are reused by access key ID alone. PUT signs an object named by the caller and its ContentType. GET first sends HeadObject, then signs GetObject; every HEAD error is treated as file-not-found, including errors that may be permissions or upstream failures. The [file-retrieval plan](../../file-retrieval.md) explains the original design but omits fields from the actual wire contract. Sources: [s3-client.ts](../../apps/go-groceries-images-meal-resolver/src/file-upload/s3-client.ts), [r2-presign.ts](../../apps/go-groceries-images-meal-resolver/src/file-upload/r2-presign.ts), [r2-presign-get.ts](../../apps/go-groceries-images-meal-resolver/src/file-upload/r2-presign-get.ts).

The source contains no filename namespace/owner restriction, object-size verification, or per-object ownership check. A valid shared pass can request signatures for supplied keys; URLs themselves grant access until expiry. Actual R2 permissions and bucket CORS are external configuration and are not defined here. Sources: [upload endpoint](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-upload.ts), [retrieval endpoint](../../apps/go-groceries-images-meal-resolver/src/endpoints/file-retrieval.ts), [signers](../../apps/go-groceries-images-meal-resolver/src/file-upload/r2-presign.ts), [S3 client](../../apps/go-groceries-images-meal-resolver/src/file-upload/s3-client.ts), [wrangler.jsonc](../../apps/go-groceries-images-meal-resolver/wrangler.jsonc).

Neither Wrangler file declares an active R2 bucket binding, KV/D1 binding, assets binding, or service binding. Storage access is through the SDK and the named environment variables. Model/YouTube logging options can emit extracted content, and frontend automatic upload logging includes a signed URL. ## Shared backend library

`ErrorWrapper` extends Error with a generic numeric statusCode. `Model` defines getModelName; `ModelInterfaceOptions` supplies identifier/modelName/skipAnyCaching; `ModelResponse` defines the internal extraction shape. `ModelSelector` supports a default client, optional allowlist, lazy async loader and per-instance Map reuse. YouTube specializes it and creates an extractor/selector per endpoint request; SDK-instance and response caches instead live at module scope. Sources: [error.ts](../../libraries/shared-backend/src/endpoints/error.ts), [models/index.ts](../../libraries/shared-backend/src/models/index.ts), [YouTube model-interface.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/model-interface.ts), [YouTube handler](../../apps/go-groceries-youtube-meal-resolver/src/endpoints/generate-meal-data.ts), [groq.ts](../../apps/go-groceries-youtube-meal-resolver/src/models/groq.ts).

The package manifest marks CommonJS while tsconfig emits ESNext modules; that source mismatch is a packaging concern requiring build/bundler verification. The root entry is empty, and workers use explicit exported subpaths. Sources: [package.json](../../libraries/shared-backend/package.json), [tsconfig.json](../../libraries/shared-backend/tsconfig.json), [src/index.ts](../../libraries/shared-backend/src/index.ts), [images types.ts](../../apps/go-groceries-images-meal-resolver/src/types.ts).
